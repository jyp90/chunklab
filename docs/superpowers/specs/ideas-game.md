# 아이디어 메모: 청킹 RTS × RPG 게임

- 날짜: 2026-09-18
- 상태: 아이디어. chunklab 도구와 **별도 프로젝트**. M3 미니게임 반응을 본 뒤 착수 여부 판단.

## 컨셉
RAG 청킹 트레이드오프를 RTS 유닛 운용 + RPG 성장으로 체득하는 게임.

## RAG → 게임 매핑
| 게임 요소 | RAG 대응 | 메모 |
|---|---|---|
| 유닛 | 청크 | 크기·속성 다양, 다수 배치 |
| 생산 건물 | 청커 | recursive=값싼 대량, sentence-window=겹치는 방어형, markdown=지형 자동 배치 |
| 자원 | API 토큰 비용 | 임베딩 호출마다 소모, 캐시=재활용 |
| 적 웨이브 | 질문 | top-k 유닛이 응전, 정답 span 덮으면 방어 성공 |
| 시야 | 검색 방식 | dense=넓고 흐림, BM25=좁고 정확, hybrid=둘 다 |
| 테크 트리 | 임베딩 모델 | 로컬(무료·약함) → OpenAI small → large |
| 성장 | 실험 이력 | 문서 변경에도 살아남는 설정이 레벨업, 회귀=데스 |
| 보스 | 멀티홉 질문 | span 여러 개 동시 커버 필요 |
| 맵 | 문서 | PDF=지형 파싱이 험한 맵 |

## 핵심 재미 가설
큰 유닛(2048 청크)은 뭐든 막지만 자원 폭식 + IoU 감점. 작은 유닛은 싸지만 span을 놓침. 실제 청킹 트레이드오프를 몸으로 배움.

## 냉정한 제약
- 게임 개발은 도구의 3~5배 시간. 주 10~15h로 1년+.
- 수익화·타깃이 도구와 완전히 다름 (SaaS → Steam/itch 또는 교육 B2B).
- 도구와 동시 진행 불가.

## 실행 순서
1. chunklab 도구 M1~M3 그대로. 메트릭 엔진 = 게임 룰 엔진으로 재사용 가능.
2. M3 마케팅 미니게임을 이 컨셉의 축소판으로: 슬라이더 → 웨이브 방어 애니메이션. 1~2주.
3. 미니게임 반응이 도구보다 뜨거우면 별도 스펙으로 게임 프로젝트 시작.
